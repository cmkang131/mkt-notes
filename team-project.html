팀 프로젝트 (Group 3)

팀 프로젝트 30% · 산업을 골라 제품 차별화 + 그 가격 전략 · 2026-10-21 정리

1과제 개요와 진행 상황

  • 주제: 산업 하나를 골라 제품 차별화 + 그 가격 전략 (수업 노트 기준). 성적 비중 30%.
  • 교수님 지시 (10/15 공지 메일): 11월 첫째 주 전까지 팀원들과 관심 있는 제품/서비스 논의 시작. 각 조 볼드 처리된 첫 번째 학생(=창민)이 메일 스레드 만들어 연락 주도.

팀 구성 (Group 3, 5명)

  • 팀장: 강창민. 조 볼드 첫 번째 이름, 연락 총괄
  • 팀원 4명. 학과는 컴퓨터공학·무은재·반도체공학·전자전기공학 등으로 다양함
  • 10/13~15: 교수님이 조 편성 확정, 메일 주소 공유 (공지 3회).
  • 10/16: 팀장이 팀원들에게 단톡방 개설용 연락처 요청 메일 발송.
  1. 팀 전원 연락망 정비 → 카톡 단톡방 개설
  2. 첫 모임 전 주제 후보 2~3개 준비. 수업 모형을 적용할 수 있는 산업
  3. 첫 모임 일정 잡기. 11월 첫째 주 전, 월·수 수업 직후가 편함
  4. PLMS에서 산출물 형식·최종 마감 확인
  5. 첫 모임에서 역할 분담 정하기

2주제 선정: 후보 비교

후보 v2 (2026-10-21): 세 후보 모두 수업 모형 + 실제 데이터/시뮬레이션

  • 후보 1: AI 구독 vs 사용량 과금: 정액(묶음) vs 종량제. 설문(학생 약 100명, Van Westendorp 4문항)으로 지불의사 수요곡선 추정 + GPU 시세로 원가 추정 → 해 찾기. 데이터 접근성 최고, 팀 전원이 실사용자.
  • 후보 2: 전기차 충전 다이내믹 프라이싱 + 배터리 구독: 보완재 모형의 확장. 다이내믹 프라이싱+시뮬레이션은 수업이 안 다룬 방법론이라 "최적화 수업화" 위험 → 피크/오프피크 두 버전 정적 가격으로 축소하면 살아남.
  • 후보 3: HBM vs 범용 DRAM: 차별화 → 탄력성 하락 → 가격 결정력. 차별성은 최고지만 B2B라 수요곡선을 추정할 데이터가 없어 실행 불가능에 가까움 → 점수 리스크 최대.

교수님 의도 분석 (근거와 추론 구분)

  • 근거: "최적화 수업이 아니라 마케팅 분석 수업", "숫자로 어떤 결정?", 숙제 = 수업의 재적용, 손채점 + "함수만 맞으면 OK", 10/15 메일 "관심 있는 제품/서비스".
  • 추론 (추측): 과제 의도는 수업 프레임 전체(차별화 → 수요 추정 → 해 찾기 → 결정)를 새 산업에 완주하는 것. 기술 난이도가 아니라 모형 설정과 해석이 점수.
  • 재평가 순위: 1번 > (안전 대안: v1 캡슐커피) > 2번(축소 시) > 3번. 추천: 1번, 발표 구조는 교수님 파이프라인 순서로.

3실행 계획 (후보 1 확정 시)

  1. 산업 선택생성형 AI 구독/API 시장 (소비자 구독 + 개발자 API, 한국 학생 시장 중심). 범위를 좁혀야 수요 추정이 현실이 됨. 수업 모형이 전부 B2C 사례라 그대로 대응됨.
  2. 차별화 설계무료 / Plus급 / Pro급 / API 종량제의 버전 구조와 차별화 축(모델 품질·사용량 상한·속도)을 실제 요금표에서 관찰해 정리. 수업의 제품 차별화 단원(Basic/Premium)과 같은 구조.
  3. 수요 추정포스텍 학생 약 100명 설문 (지불의사 4문항 Van Westendorp + 사용 빈도 + 정액 vs 종량 선호 + 버전 선택). 누적 분포 → 수요곡선, 피벗+회귀로 탄력성. 원가는 GPU 시간당 시세로 추정 + ±50% 민감도. "직접 한 걸 제출하라"는 요구의 답.
  4. 최적화변수(구독료, 토큰 단가) → 목적함수(이익) → 제약(수요곡선, 원가 하한) → 해 찾기. 정액/종량/하이브리드 3구조 비교 + 그림자 가격 해석. 퀴즈·숙제와 같은 도구 = 의도에 부합.
  5. 결정"이 숫자로 어떤 결정?": 결론 한 문장 + 근거 숫자 2~3개. 교수님이 매 수업 묻는 질문.

역할 분담 (초안, 첫 모임에서 확정)

  • 강창민 (팀장): 모형 설계 + 해 찾기, 추론 원가 추정 (모델 경량화 연구 중이라 토큰 원가 구조를 가장 잘 앎)
  • 팀원 A: 공개 요금·GPU/하드웨어 원가 데이터 수집
  • 팀원 B: 설문 문항 설계 + 통계 분석(회귀·탄력성)
  • 팀원 C: 설문 배포·수거 총괄 + 수요곡선 엑셀 정리
  • 팀원 D: 발표 자료·스토리라인

타임라인 (11월 첫째 주 목표)

  • ~10/24: 팀 연락망 정비 → 단톡방 개설
  • 첫 모임: 10/30(금) 후보 (10/29 시스템 시험 당일이라 피함), 여의치 않으면 단톡방 비동기 확정
  • ~10/31: 설문지 확정 + 공개 데이터 수집 완료

  • 11/3~11/6: 추정 + 최적화 (11/5 UGRP 중간보고서와 겹침. 이 구간 분석 리드는 팀원 A·B, 팀장은 검수)
  • 11/6~11/9: 결정 + 발표/보고서 초안
  • [확인] 산출물 형식(발표/보고서), 최종 마감일, 발표 시간: PLMS 확인 필요
